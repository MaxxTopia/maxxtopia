# Maxxtopia contributor runbook

This repository powers maxxtopia.com, an Astro 5 static site deployed to
Cloudflare Pages. Preserve the existing visual system, product architecture,
and unrelated work in the working tree.

## Read first

Before editing, read:

- `CLAUDE.md`
- `_IF-YOU-LOSE-CLAUDE.txt`
- `TROUBLESHOOTING.md`
- `DEPLOY.md`
- the relevant README or runbook
- the newest matching notes under
  `C:\Users\Diggy\projects\_CONTINUITY\snapshot\claude-memory`

Inspect `git status --short --branch` and recent history before changing files.
Never reset, clean, discard, overwrite, or reformat unrelated changes.

## Architecture

- Product data lives in `src/data/products.ts`.
- Product pages are generated by `src/pages/[slug].astro`.
- Bespoke product heroes live in `src/components/*Hero.astro`.
- Public static assets live under `public/`.
- The main site deploy is separate from the `tickets-worker` and
  `votes-worker`; do not deploy either worker unless the task explicitly
  includes it.

## Build and local verification

Use Node 20, matching CI.

```powershell
npm ci
npm run build
npm run preview -- --host 127.0.0.1
```

For an existing install, `npm run build` is sufficient unless dependencies are
missing or stale. Verify every changed route in a browser at desktop and mobile
sizes, check the console, and confirm referenced assets return 200. Bespoke
heroes must retain a meaningful animated presentation even when Windows reports
`prefers-reduced-motion: reduce`, because the animation communicates the
feature; avoid high-intensity shake or strobing.

## Change safety

- Commit only the files intended for the current task. Never use `git add -A`.
- Keep secrets, `.bot-setup.local.env`, Wrangler state, generated screenshots,
  and temporary audit files out of commits.
- Keep shipped PowerShell, batch, and command files ASCII-only.
- Do not add AI or Claude co-authorship trailers.
- Prefer uniquely prefixed component classes and IDs. Runtime-created elements
  need global styles scoped beneath a unique root.
- Preserve the lower content of product pages when replacing a generic hero.
- Before shipping, run:

```powershell
git status --short --branch
git diff --check
git fetch origin main
git log --oneline origin/main..HEAD
```

An automated product-data commit may update `main`. If it does, integrate the
new remote state without losing unrelated local edits, then rebuild.

## Ship

Production publishing requires Diggy's explicit approval. Once approved:

1. Run `npm run build` and complete route-level browser checks.
2. Review and stage only the intended files with explicit paths.
3. Commit without co-author trailers.
4. Push the current `main` branch to `origin`.
5. `.github/workflows/deploy.yml` runs `npm ci`, builds, and deploys `dist` to
   Cloudflare Pages project `maxxtopia` on every push to `main`.
6. Watch the matching GitHub Actions deploy run to completion.

Do not run a separate website Wrangler deploy after a normal push unless the
documented GitHub workflow is unavailable and Diggy approves the exception.

## Production verification

After the deploy succeeds:

```powershell
curl.exe -sI https://maxxtopia.com
curl.exe -sI https://maxxtopia.com/snipemaxxer
```

Confirm HTTP 200 and the expected security headers, then visually inspect the
changed live route at desktop and mobile sizes. Report build, test, commit,
push, deploy, and verified-live states separately.

## Continuity

After meaningful work, update a vendor-neutral project note with the scope,
decisions, files changed, verification, current live state, unresolved risks,
Diggy-owed tests, and the exact next action. Refresh the portable continuity
snapshot when authorized; an off-machine copy is still required for real
disaster recovery.
